# Stage 6 stock

Pantry reads Grocy's stock overview and volatile lists, products, locations, quantity units, resolved product quantity-unit conversions, product barcodes, stock journal, and authenticated OpenAPI specification through the account's Room cache. Product detail reads stock details, location totals, individual entries, and price history. Refresh fetches server changes. Failed or malformed reads preserve the last valid response and mark it cached; 401/403 responses deny access even when a last-good response exists.

Search matches product names or exact barcode strings from Grocy's `product_barcodes` table. The scanner destination accepts a manually entered barcode and matches only that table. There is no camera permission, camera capture, or external barcode lookup. Overview filters include in-stock, use soon (Grocy due, overdue, and expired), running low (Grocy missing/minimum stock), opened, and actual stock location. Due/missing classifications come from Grocy rather than local date or minimum-stock calculations. Opening Pantry on in-stock pins Use soon and Running low above the rest of the list. Product detail includes own and aggregated quantities, opened stock, entries, locations, dates, current/average/last prices, and price history. Prices, IDs, dates, and barcode strings retain their normal representations.

The booking form supports purchase, consumption, opening, transfer, inventory, and spoilage. Quantity input and output use the independent fractions module. Parsed decimal values are multiplied by Grocy's resolved conversion factor into stock units; numeric JSON and cached server values remain decimal numbers. Price input is explicitly per stock unit and accepts ordinary decimals. Tare purchase/inventory use Grocy's gross-weight semantics; consume/spoilage explicitly book net amounts. Transfer is disabled for tare products and opening is disabled when Grocy's product setting disables it. Grocy validates stock availability, entry selection, and booking rules.

All bookings enter the existing account-bound durable outbox before dispatch. The screen shows pending/in-flight/confirmed/failed/needs-review operation records separately from confirmed server quantities; it does not predict a stock balance locally. Refresh drains only pending operations and rereads stock, journal, locations, and detail. Confirmed operations are never replayed. Ambiguous additive operations have no fabricated expected representation and retain Stage 5's needs-review behavior. Undo appears only when the server's authenticated OpenAPI advertises the endpoint, using an outbox POST like other mutations. Transaction undo groups multi-entry bookings, including both sides of a transfer; booking undo is a fallback when transaction undo is unavailable; Grocy remains the final authority on which bookings can be undone.

Stock requires a verified explicit ADMIN or STOCK grant. Unknown permissions and chores-only child grants never fetch or display cached stock. This is conservative app visibility, not a replacement for Stage 1's unresolved server/proxy access-control issue. Individual server denials also clear the visible stock data. No proxy is added here.

The gate is `mise run stage:6`. Unit and Room/MockWebServer tests cover payloads, conversion, permissions, denial over cached data, allowed read paths, all mutation routes, pending/confirmed records, and undo. A Robolectric JVM integration test uses actual Room and the production HTTP/cache/outbox repositories against both disposable Grocy containers. It creates a synthetic product, resolved purchase conversion and barcode; buys 1.25 packs × 4 units, consumes 1.5 units, and verifies Grocy reports 3.5 units with the matching purchase/consume journal. It also exercises open, transfer, inventory, spoilage and supported undo. Independent official API reads compare the server data used by Grocy's web app. This is container interoperability, not browser or Android device UI automation. Synthetic fixture objects, keys, and users are removed after the test.

Pantry rows can show extra attributes and Grocy product userfields chosen in Settings → Stock → Shown details. See [STOCK_DETAILS.md](STOCK_DETAILS.md).
