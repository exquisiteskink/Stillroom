# Recipes and meals

Stage 10 uses Grocy's `recipes`, `recipes_pos`, `recipes_pos_resolved`, `meal_plan`, and `meal_plan_sections` records. Generated day/week/shadow recipes are not offered for editing. The configured server's sections appear in the meal editor, including its unsectioned entry. Recipe, product, and note entries retain their server types.

Grocy remains authoritative for desired servings, resolved ingredient amounts, rounding, stock fulfillment flags, units, and conversions. Scaling saves `desired_servings`; it never rewrites base ingredient amounts. A fraction editor retains the exact original decimal when its input is unchanged, even when its initial display is an approximation. Changed fraction input is converted once to a decimal when Save is pressed.

Missing ingredients use native scaled ingredient amounts and fulfillment flags, converted to stock units and compared with actual stock, then added through the existing shopping outbox to the selected list. Grocy 4.7.1’s resolved missing field does not account for the conversion in the tested 2:1 case, so Stillroom computes the shortfall using the server’s conversion and stock records. Already outstanding quantities on that list are deducted. Unconfirmed shopping changes must be reconciled first. Consumption aggregates resolved requirements by effective product, converts to stock units, and opens a review. Confirmation rechecks the recipe and available stock online, then uses the existing stock consume outbox with native `recipe_id` attribution. The same review has stable operation IDs; it cannot book a second consumption. Interrupted or partially queued reviews require inspection of Pending changes. Stock journal undo uses the existing stock screen.

Variable ingredient labels are preserved and editable. They must be resolved to measured quantities before consumption; Stillroom does not guess them. Unknown unit conversions also block consumption. Recipe/stock/shopping/meal operations require explicit grants in addition to upstream checks. A chore-only child key cannot load this screen.

Cooking mode shows instruction steps, ingredient checkboxes, and multiple elapsed-time countdowns, and keeps the visible Android window awake. Checkboxes do not consume stock. Timers are local cooking aids while the screen is open; no background alarm service is installed.

A shared text URL opens review before any fetch or save. Reading metadata is an explicit anonymous HTTPS GET to a public host, with bounded responses, no redirects, cookies, Grocy headers, or household payload. Schema.org Recipe JSON-LD supplies suggestions only. Multiple recipe candidates and unrecognized yields open manual review without guesses. Every ingredient requires manual selection of an existing product, a supported unit, and a reviewed amount, or explicit exclusion. No products are created by import. The source remains a plain source link in Grocy's sanitized recipe description. A reviewed recipe and its mapped ingredient follow-ups are durable account-scoped outbox records.

Images are selected and reviewed locally, re-encoded to JPEG, and uploaded to Grocy's `recipepictures` file group before associating their filename. Authenticated image reads are account cached. Uploads require a connection and have no automatic retry on uncertain outcomes. Removing an image clears the recipe's native picture field; it does not delete an image that another recipe might still reference.

References: [Grocy API](https://demo.grocy.info/api), [Schema.org Recipe](https://schema.org/Recipe), [Android receiving shared content](https://developer.android.com/develop/ui/compose/sharing/receive), [jsoup](https://jsoup.org/).

Run `mise run stage:10` against the already-running local Grocy on port 9283. The gate mints and revokes a temporary test key, creates only synthetic fixture records, and removes them after the test. It does not start containers or deploy services. The native test verifies a two-serving recipe scaled to four with a 2:1 unit conversion: base ingredient 1.25 remains unchanged, requirement is 5 stock units, 3 are available, 2 go to the chosen list, refill permits a single reviewed consumption of 5, and the native journal carries the recipe ID. It also verifies undo, recipe/ingredient/meal CRUD, images, source retention, and durable mapped import. API reads inspect the same records used by the web app; this is not a browser or physical-device test.
