# Stillroom visual system review

Scope: source audit of all release Compose screens and their subflows. No screenshots, phone or emulator inspection performed. This document specifies a redesign; it does not claim UI changes or rendered verification. The scanner receives priority because it is the user's stated problem. Existing capabilities only; no added Grocy operations. Sources below are relative to `app/src/main/java/app/stillroom/`.

## Principles applied

1. **Hierarchy / signal to noise:** food quantity, selected operation, due status and commit action precede administrative details. One filled primary action in each task state.
2. **Gestalt proximity and similarity:** use proximity within groups, a larger gap between groups, and identical row anatomy for the same object. A card must denote a bounded object or decision, not decorate every fragment.
3. **Recognition over recall / progressive disclosure:** name the product and operation throughout scanning. Present the transaction form before the product's price history, journal and metadata. Restage existing fields; retain data and permissions.
4. **Semantic color / redundant coding:** accent means selected or primary; red means error or destructive consequence. Neutral text names normal, due and confirmed states. Never require color to understand stock or sync status.
5. **WCAG 2.2 AA and native Android adaptation:** contrast and enlarged text govern hierarchy; 48dp interactive targets and system dark theme govern layout. Compose dp is the platform implementation unit; sp must scale with font settings.

Space: `4, 8, 16, 24, 32, 48`dp. Use 4dp only for internal label/value separation. Page gutters 16dp phones, 24dp tablets. Related controls 8dp; form field groups 16dp; section transitions 24dp. Form width max 560dp, detail content max 720dp; center within remaining content pane on wide screens. List rows min 64dp, flexible height; touch controls min 48dp. No fixed text-containing height.

Radius: 8dp fields/buttons/cards; 16dp sheets/dialogs; navigation active indicator may use platform pill shape. Elevation: 0dp page/list/card/nav; 6dp modal/menu only. Border: 1dp, one outline token; 2dp focus boundary. No permanent ornamental rules, shadows, gradient, glass or background photography. User recipe photos carry recognition value and remain optional content.

## Shared component rules

- **App bar:** neutral surface and 20sp primary-text title, 64dp minimum height. Remove the 4dp accent line. One labeled scan action on the relevant task screen; quiet existing utility actions use icon plus visible label when not universal. Search/back remain universal icons with accessible names. Account identity is quiet text on account management, not a competing accent.
- **Buttons:** primary filled accent; secondary outlined neutral; tertiary neutral text. Destructive action red text in confirmation; never imply primary=delete everywhere. 48dp minimum hitbox, 16dp horizontal padding, 8dp icon-label gap. One primary per active task state. Pending state preserves width and label context.
- **Inputs:** label above field, 8dp label-field gap; full available form width. Supporting or validation line immediately below at 14sp. Match quantity/date/unit field widths and alignment. Errors use text and outline; no distant generic error as the only validation. Existing long chip choice strips become labeled select fields opening the existing choices; no new domain behavior.
- **Lists:** product name left, quantity and unit right; due or sync message below name. Start all names at the same baseline/column. Use full row hit area; trailing actions stay 48dp. No giant photograph for an empty list. Completed rows retain legible contrast and add check/text; do not fade essential names below AA.
- **Nav / tabs:** bottom nav or existing tablet sidebar, icon plus label, neutral unselected state, accent current state. Selected subsection uses the same active treatment everywhere. Preserve large-font scrollable behavior; do not shrink labels. Actual destinations and filters must not look interchangeable.
- **Dialogs / sheets:** title, bounded body, cancel plus one committing action. Body scrolls; actions remain reachable above IME. Simple confirmations stay dialogs; existing complex edit/import forms become full-height task panes/sheets with the same tokens. This restages forms rather than inventing actions.
- **Status / toast:** persistent offline/pending/review states use compact inline banners attached to their affected task. Transient success may use existing feedback channel; do not specify new backend/undo behavior. No success green accent, no metaphors for loading. Loading holds known content; first load shows explicit operation text.

## Highest-priority visual fixes

- **Major:** Scanner controls exceed short screens/IME and bury transaction controls inside product metadata (`ScannerScreen`, `CameraScanner`, nested `StockScreen`). Apply one scroll owner, adaptive preview, task-focused result pane. Principles: adaptive layout, progressive disclosure, task completion.
- **Major:** Matched scan foregrounds “Scan next” before the stock transaction and lacks unique primary action. Apply product/context → operation → fields → commit. Principles: hierarchy, error prevention.
- **Major:** Meal plan omits visible day/section even though data is sorted by them. Apply day grouping and meal metadata. Principle: recognition over recall.
- **Major:** Recipe detail has multiple competing filled actions; cooking mode preserves unrelated management above it. Restage existing tasks and one primary per state. Principle: hierarchy, cognitive load.
- **Major:** Hardcoded kitchen tones remain separate from wallpaper-derived dynamic theme; accent also paints headings, dividers and status. Normalize neutral surfaces and single accent roles. Principles: semantic color, consistency.
- **Minor:** Decorative meal/empty/placeholder photos consume space without representing objects. Remove them; preserve authentic recipe photographs. Principle: signal to noise.
- **Minor:** Off-grid 20/12/10/6/2dp styling and 34/30sp type undermine similarity. Apply shared tokens. Principles: Gestalt similarity, alignment.

## Removals

Remove ornamental today hero, empty-state photo illustrations, fake recipe photography, permanent accent separator, accent section titles, clay surfaces, repeated primary buttons and duplicate padding in nested scanner detail. Collapse always-open list creation and recipe-import fields into existing task states. Replace giant choice chip strips with labeled select views of the same choices. No data, backend feature, permission, server authority or confirmation guard is removed.

Verify text/control contrast for actual pairs; ensure no clipping, overlapping controls, inaccessible actions or camera controls on untested translucent backgrounds.
