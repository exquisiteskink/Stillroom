# IA implementation handoff

Implemented the authorized redesign in these UI files only: `ShoppingScreen.kt`, `ShoppingForms.kt`, `RecipeScreen.kt`, `HouseholdScreen.kt`, `CatalogScreen.kt`; updated host Compose regressions in `ShoppingFormsTest.kt`. Shared tokens/components and scanner/stock implementation are owned by other collaborators. Domain, data, account grants, payload precision, cache, and outbox semantics remain unchanged.

- **Shopping:** one searchable shopping-list selector; Create list reveals its form; Add item stays the main action; group controls have a label; conflicts expose Review change rather than take over the screen automatically. Editor/purchase/review stages scroll with IME and Back returns locally. At the store retains Add stock. Item status says Pending sync / Saving / Needs review / Could not save. Product/unit/location/store use bounded searchable existing-record pickers.
- **Purchase review:** package due date starts blank and is optional for this existing shopping flow. A nonblank invalid date blocks submit and explains the required format. Quantity/price have inline errors. Untouched stored amounts retain their precision-aware input behavior. This does not relax scanner due-date requirements.
- **Meals:** Meal plan replaces the inaccurate This week label; each entry includes its actual day/section. Import form is disclosed by Import recipe. Start cooking is the unique filled action on detail; shortage/stock/servings controls are quiet. Cooking is isolated from editing/stock controls with local Back, named row checkbox targets, existing timers and step controls. Fabricated photo placeholder removed; a recipe only displays its own cached photo. Detail shows write errors/review status.
- **Household:** empty due groups omitted; overall empty/loading states named; pending chore/task completion remains unchecked and shows waiting feedback via shared KitchenCheckRow. Existing description/instructions are visible with the record. Assignment/category/recurrence controls use labeled pickers. Labeled checkbox rows, inline required/date/integer validation, scrolling dialogs.
- **Records:** catch-all tab renamed Records as the agreed implementation scope. Explicit Record type picker. Correct Add/Edit singular object names, empty/loading/error states, empty charge history, operation status. Product advanced fields are disclosed but remain present in the payload model; unsupported custom values remain preserved. Existing-reference selectors and labeled checkbox rows replace long strips/unnamed targets.

Principles: recognition over recall (named records and pickers); progressive disclosure (list creation/import/advanced settings); visibility of status (pending is not completed); error prevention (package dates never guessed); user control (local Back); consistency (shared labels/pickers/tokens); WCAG 2.2 name/role/value (row-toggle labels).

Validation: added two meaningful host Compose cases before implementation for an initially empty purchase due date and blocking an invalid date while preserving its input. Existing precision regressions adapted to labeled fields/searchable choice controls. No Gradle command was run by this collaborator to avoid concurrent build execution; the root agent performs integrated build/test validation. No device validation is claimed. The fuller IA document remains the design reference; contextual redistribution of Records and exact object deep links require coordinated shell routing and were not implemented in these owned screens.

Critic revision: when an empty collection has a failed read, Recipes/Meal plan/Shopping/Chores/Tasks/Records show the shared ErrorState with an explicit refresh retry. Busy collections show loading; only an error-free settled read shows the empty claim. Missing recipe detail also exposes retry after a failed read. Existing cached rows stay visible with inline error feedback. No new model/domain operation or additional test harness was introduced for this conditional rendering change; integrated validation remains with the root agent.
